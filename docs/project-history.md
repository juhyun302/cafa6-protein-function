# 프로젝트 경과와 문제 해결 기록

구조 기반 branch를 선택하고 소규모 점검에서 대규모 처리·앙상블로 연결한 경과를 정리했습니다. 원래 코드·저장된 노트북 출력·발표자료와, 사용자가 제공한 과거 대화 재구성 요약을 대조했습니다.

문서 작성 기준: 2026-11-06. 아래 순서는 진행 흐름을 설명하며, 요약에만 있는 날짜를 확정된 실행 일자로 사용하지 않았습니다.

## 1. 초기 구상에서 구조 검색으로

초기에는 ESM 임베딩과 CNN 등의 서열 모델, Azure 인프라와 데이터 연결을 검토했습니다. 개인 손글씨 구상에는 ESM-3·Foundry·RAG/LLM도 등장하지만, 최종 구현 완료 목록으로 취급하지 않습니다.

이주현의 실제 담당은 기존 AlphaFold DB 구조와 Foldseek 검색 결과에서 기능 정보를 가져오는 branch로 정리되었습니다. 팀의 서열·증거 기반 예측과 결합하는 역할입니다. 서열 모델 원본은 홍지승 작성 실험으로 구분합니다.

새로운 구조 모델 학습보다 기존 구조 검색·annotation 전이를 택한 배경은 과거 회고에 남아 있습니다. 회고의 초기 예산은 당시 제약이며 현재 사용 비용의 실측값이 아닙니다.

## 2. 소규모 점검: 검색 성공과 예측 성공 구분

구조를 받았다는 사실만으로 GO 예측이 만들어지지는 않습니다.

~~~text
입력 단백질
  → 구조 확보 여부
  → Foldseek 검색 결과 존재 여부
  → hit 대상의 GO annotation 존재 여부
  → GO 점수 생성 여부
~~~

회고에는 초기 100개 실험에서 구조 확보 72개·미확보 28개, 기능 전이 69개로 원인을 나눠 분석한 기록이 있습니다. 원본 채팅 전체와 그 실행의 입력·산출물이 함께 보존되어 있지는 않아 수치는 회고 기록으로만 다룹니다.

### 다른 100개 실습과 섞지 않기

Git 이력의 별도 실습 파일을 직접 대조한 결과입니다.

| 확인 항목 | 결과 |
| --- | --- |
| ‘최종 실습’ 입력 목록 | 서로 다른 ID 100개 |
| 성공 로그 | 68개 |
| 미확보 로그 | 32개 |
| 두 로그의 교집합 | 0개 |
| 두 로그의 합집합 | 해당 입력 100개와 정확히 일치 |
| train 목록 앞 100개와 위 입력의 교집합 | 11개 |
| 초기 28개 누락 목록 | 전부 train 목록 앞 100개에 포함 |

따라서 72/28과 68/32를 같은 표본의 결과로 합칠 수 없습니다. 입력·시점이 다른 실험일 가능성이 있으며, 69개 전이 기록이 어느 표본에 대응하는지 확정하지 않습니다.

당시 일부 다운로드 코드는 통신 실패도 구조 미확보로 분류할 수 있었습니다. 로그의 ‘미확보’를 AlphaFold DB에 구조가 없다는 증명으로 확대하지 않습니다.

## 3. 대규모 검색: 배치 결과를 후속 처리에 연결

원래 Foldseek 코드에는 배치 크기 5,000, max-seqs 20, alignment 생성과 7열 TSV 출력 설정이 있습니다. Azure 제출 노트북에는 CPU 클러스터 설정이, 발표자료에는 32코어 전략이 남아 있습니다.

보존된 노트북 실행 출력:
- 30개 배치 파일 병합
- 검색 hit 2,488,745행
- 전체 ID 목록 224,309개
- 검색 결과에 등장한 query ID 145,521개

마지막 값은 검색 결과 커버리지입니다. 구조 파일 실물의 개수를 새로 집계한 값이 아닙니다. 또한 마지막 배치가 가득 찼는지 알 수 없으므로 30 × 5,000을 실제 처리 단백질 150,000개로 확정하지 않습니다.

병합·ID 정리·GO 전이 단계를 연결한 구현과 기록은 [개인 기여](contributions.md), 수치 추출 출처는 [근거 자료](evidence/README.md)를 참고하세요.

## 4. GO 전파 후 후보 관리

회고에는 69개 query에 대한 GO 예측이 약 1,827행에서 조상 전파 후 약 100,380행으로 증가한 기록이 있습니다. 이어 Top-300·500·1000을 비교한 후보 제한 기록도 있습니다.

| 후보 제한 | 회고에 기록된 행 수 |
| --- | --- |
| Top-300 | 19,005 |
| Top-500 | 29,150 |
| Top-1000 | 50,586 |

원본 TSV가 현재 없으므로 위 수치를 재계산하거나 최적 Top-N을 확정하지는 않았습니다. 이 기록은 후보 수·메모리·출력 크기를 관리한 문제 해결 과정을 설명하는 보조 자료입니다.

### 현재 코드의 서로 다른 제한 단계

- normalize: namespace 분리 전 단백질별 전체 GO 후보에서 Top-50·최소 상대 점수 0.2
- make-submission: 상향 전파 후 BP·MF·CC 각각 단백질별 Top-500

전파는 조상 term을 추가하므로 앞 단계와 뒤 단계의 후보 제한이 서로 다릅니다.

## 5. 노트북 안의 여러 결과를 한 실행으로 이어 붙이지 않기

저장된 실행 출력과 Markdown 설명이 다른 경우도 확인했습니다.

| 출처 | 기록 |
| --- | --- |
| GO 전이 셀 실행 출력 | query 70,557개·644,529행 |
| 정규화 셀 실행 출력 | MF 130,879 + BP 313,065 + CC 176,985 = 620,929행 |
| 별도 Markdown 요약 셀 | 단백질 127,438개·2,188,445행 |

서로 다른 실행이나 갱신되지 않은 설명일 수 있습니다. 현재 자료만으로 연결 관계와 최종 제출에 사용된 산출물을 확정하지 않습니다. 공개 문서에서는 출처별 기록을 분리했습니다.

## 6. 내부 평가와 공식 대회 성적

회고의 초기 내부 평가 기록:
- F-max 평균 0.1766
- MF 0.3022, CC 0.0831, BP 0.1446
- S-min 평균 7.3611

F-max 세 값의 산술평균은 반올림하면 0.1766과 일치합니다. 이 일관성이 평가 코드·데이터 분할·정보량 가중치·누수 방지 검증까지 입증하는 것은 아닙니다.

특히 대회 test에는 당시 정답이 공개되지 않았으므로, 이 수치가 어떤 labeled holdout에서 계산되었는지 확인해야 합니다. 공식 점수나 팀 최종 점수와의 개선율로 사용하지 않습니다.

검증 query를 annotation donor·참조 DB에서 분리하는 방식은 논의·제안 기록입니다. 현재 자료만으로 엄격한 holdout 평가를 완료했다고 주장하지 않습니다.

공식 성과는 별도 기록입니다. 팀은 최종 Private 리더보드 92위·0.38737·은메달을 기록했습니다. [Kaggle 근거와 공개 범위](experiments.md)

## 7. 재구성 요약의 사용 범위

자료는 원본 채팅 전체가 아닌 재구성 인수인계입니다. 현재 README·코드를 다시 요약한 부분도 있어, 이를 당시 작업에 대한 독립 증거로 중복 계산하지 않습니다.

- 원래 코드·목록·저장된 출력: 구현과 기록을 직접 확인하는 자료
- 발표자료: 당시 접근과 구성의 설명
- 대화 재구성 요약: 설계 이유·시행착오의 보조 맥락
- 초기 설계·제안: 수행 사실이 확인되지 않은 구상

이 문서는 과거 작업의 설명을 보강합니다. 현재 패키지·CLI·가상 데모·테스트는 [후속 정리](reorganization.md)로 구분합니다.
