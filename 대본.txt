1. <목차> 
"안녕하세요. 3D 구조 기반 예측 파트를 설명드리겠습니다
입력된 단백질에 대해 구조 기반 유사도 검색을 먼저 실행하고, 여기서 나온 방대한 결과 중 특정 기준에 따라 노이즈를 제거하여 데이터를 정제합니다.
이렇게 정제된 결과는 다른 모델들의 결과와 합쳐져, 맨 오른쪽의 최종 예측 확률을 산출하는 데 기여하게 됩니다."
저는 Foldseek를 사용발표는 보시는 목차 5가지 순서대로 진행하겠습니다."

2. <서열의 한계> 
"저희의 목표는 단백질 기능을 맞추는 겁니다. 보통은 단백질 서열, 즉 텍스트 데이터를 분석하죠. 하지만 텍스트엔 치명적인 한계가 있습니다. 이름은 달라도 기능은 같은 경우를 놓친다는 겁니다. 화면을 보시죠. 'Mobile Device'와 'Smartphone', 글자는 완전히 다르지만 둘 다 같은 전화기 기능을 합니다.이때 컴퓨터가 텍스트만 보면 '어? 철자가 다르네? 다른 건가 보다' 하고 놓쳐버립니다. 바로 이 놓치는 데이터를 잡기 위해 저희는 3D 구조를 활용하기로 했습니다."

3. <해결책 1: Foldseek> 
"이 문제를 해결하는 도구가 바로 Foldseek입니다. 쉽게 말해 초고속 3D 모양 검색 엔진입니다. Foldseek는 서열이 달라도 3D 모양이 비슷하면 기능도 같다는 논리로 접근합니다. 생물학적으로는 이걸 원거리 상동성이라고 하는데, 어렵게 생각하실 것 없이 무늬만 다르고 본질이 같은 대상을 찾아낸다고 이해하시면 됩니다."

4. <해결책 2: 압축과 속도> 
"수많은 도구 중 Foldseek를 선택한 이유는 압도적인 속도 때문입니다. 원래 3D 비교는 연산량이 엄청나서 데이터가 조금만 많아져도 몇 달이 걸립니다. 하지만 Foldseek는 복잡한 3D 구조를 알파벳 문자열로 변환하는 압축 기술을 사용합니다. 덕분에 무거운 계산 없이, 마치 텍스트 검색하듯이 수십만 개의 데이터를 순식간에 비교할 수 있습니다. 저희 데이터가 14만 개가 넘는데, 이 대용량을 현실적인 시간 내에 처리할 수 있는 유일한 대안이었습니다."

5. <엔지니어링 전략 1: Azure & CPU> 
"이제 제가 수행한 엔지니어링 작업입니다. 14만개 대용량 데이터 처리를 위해 Azure 클라우드에 32코어 CPU 환경을 구축했습니다. 32개 코어를 활용한 병렬 처리로 수행 시간을 획기적으로 줄였고, 검색 알고리즘 특성상 GPU보다 CPU가 유리함을 파악해 비용과 성능을 모두 잡는 최적화를 수행했습니다."

6. <엔지니어링 전략 2: 상향 전파> 
"데이터를 뽑은 뒤엔 '상향 전파' 알고리즘을 적용했습니다. GO 분류 체계는 계층 구조입니다. 쉽게 말해 '손가락'이 아프면 상위 개념인 '손'도 당연히 아파야 합니다. 하지만 AI는 가끔 '손가락' 점수는 높은데 '손' 점수는 낮게 주는 실수를 합니다. 저는 자식 노드의 확률을 부모 노드로 전파시켜, 이런 데이터의 논리적 모순을 없애고 신뢰도를 높였습니다."

7. <데이터 정제> 
"다음은 데이터 정제입니다. 수만 개의 결과 중 노이즈를 없애기 위해 두 가지 필터링을 거쳐 정예 데이터만 남겼습니다. 첫째, Top-N 전략입니다. 구글 검색 첫번째 페이지처럼, 검색 대상과 유사도가 가장 높은 상위 500개만 남겨 효율을 높였습니다. 
둘째로, 99% 신뢰구간 설정입니다. 자체 분석을 통해 99% 확률로 정답인 점수 구간을 찾았고, 이를 넘는 확실한 데이터만 선별했습니다. 왜 이렇게 깐깐하게 골랐을까요? 다음 단계인 결합 과정에서, 어설픈 정보를 남발하기보다 확실한 힌트 몇 개를 던져주는 정밀한 서포터가 되어야 했기 때문입니다."


8. <결론> 
"결론입니다. 제가 맡은 구조 기반 모델은 단독 주연이 아닙니다. 팀원들이 만든 강력한 서열 모델이 메인입니다. 하지만 서열 모델이 철자가 달라서 놓쳤던 빈틈을, 방금 정제한 확실한 구조 데이터가 찾아내 메워줍니다. 마치 텍스트 검색과 이미지 검색을 같이 써서 완성도를 높이듯, 서열과 구조 데이터를 앙상블해 예측 성능을 극대화하는 것, 이것이 제가 이 파이프라인을 구축한 핵심 이유입니다. 이상입니다."
